## Task 5.1: SOP versioning service (2026-04-02)

Created the SOPVersioningService for auto-versioning on save and version
comparison. This is the first service-layer task in Phase 5.

- Service: `SOPVersioningService` in
  `server/internal/services/sop_versioning.service.go` with:
  - `CreateNewVersion(templateID, userID, changeSummary, description)`:
    Creates a new SOPVersion by deep-copying all content from the current
    version — steps, sub-steps, media references, and BOM items — within a
    single transaction. Updates CurrentVersionID to point to the new version.
    Builds ID mapping tables (old→new) so child references (media→step,
    BOM→step) are correctly remapped.
  - `CompareVersions(fromVersionID, toVersionID)`: Produces a structured
    diff between two versions of the same template. Matches steps by order
    position, detects added/removed/modified steps with field-level change
    detail. Compares BOM items by name+unit key. Reports description changes.
  - `deepCopyVersion(tx, fromVersionID, toVersionID)`: Internal method that
    handles the transactional deep copy of steps, sub-steps (preserving
    display order), step-level and sub-step-level media (preserving file
    references and order), and BOM items (remapping SOPStepID references).
- Types: VersionDiff, StepSummary, StepDiff, FieldChange, StringChange,
  BOMSummary — structured diff output types for API consumption.
- Repository additions:
  - `BOMItemRepository`: added `GetByVersionIDWithTx` and `CreateBatchWithTx`
    for transactional reads and batch creates during version copying.
  - `SOPStepMediaRepository`: added `GetByStepIDWithTx`,
    `GetBySubStepIDWithTx`, and `CreateBatchWithTx` for transactional media
    operations during version copying.
- Tests: `sop_versioning.service_test.go` with unit tests for:
  - `compareSteps` — no changes, title change, instructions change,
